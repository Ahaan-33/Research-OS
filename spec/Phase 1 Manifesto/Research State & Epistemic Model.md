# Research OS – Research State & Epistemic Model

### Version 0.1

---

# Purpose

This document defines the central conceptual model of the Research OS.

Previous documents described

- why the system exists,
    
- how it should feel to use,
    
- how knowledge is organised.
    

This document answers a deeper question:

> **What is the Research State?**

Everything within the Research OS exists as a consequence of this definition.

---

# Research State

The Research State is the canonical representation of an active scientific project.

It is **not** merely a collection of notes.

It is the continuously evolving representation of the project's current scientific understanding.

Formally,

> **Research State = Immutable Evidence + Mutable Interpretation**

The Research State contains

- every Note Block,
    
- every metadata assignment,
    
- every explicit relationship,
    
- every derived relationship,
    
- every semantic similarity,
    
- every organisational statistic,
    
- every confidence estimate,
    
- every active thread.
    

Every user-facing interface is simply a projection of this single object.

---

# Canonical Object

The Research State is the only authoritative representation of a project.

Everything else is derived.

This includes

- Dashboard
    
- Semantic Map
    
- Thread View
    
- Publication View
    
- Timeline
    
- Reports
    
- Review Panels
    
- Graph Visualisations
    

Each is a different projection of the same underlying state.

Conceptually,

```
Research State

↓

Projection Function

↓

User View
```

No view owns information.

Every view observes the same continuously evolving system.

---

# Immutable Evidence

Scientific observations are permanent.

Once captured, they are never discarded because they represent objective historical evidence.

Examples include

- experimental observations
    
- protocols
    
- hypotheses
    
- literature summaries
    
- measurements
    
- conclusions
    
- failed experiments
    
- rejected ideas
    

Negative results remain first-class scientific artefacts.

The system never forgets evidence.

---

# Mutable Interpretation

Although evidence remains permanent, its interpretation continuously evolves.

Metadata does not describe

> what was believed when the Note Block was written.

Instead, metadata represents

> the current best interpretation of that evidence.

As new information enters the system,

- confidence changes,
    
- priorities change,
    
- thread assignments evolve,
    
- synthesis improves,
    
- relationships strengthen or weaken,
    
- organisational structure reorganises.
    

The Research State therefore remains alive throughout the lifetime of a project.

---

# Living Representation

The Research State is intentionally not historical.

History exists through

- immutable Note Blocks,
    
- revision history,
    
- version control.
    

The graph itself should instead answer

> **What do we currently believe to be true?**

The graph therefore remains continuously updated.

It should rarely become frozen.

---

# Knowledge vs Interpretation

The Research OS deliberately separates evidence from interpretation.

Evidence consists of

- observations,
    
- experiments,
    
- literature,
    
- hypotheses,
    
- measurements.
    

Interpretation consists of

- confidence,
    
- organisational relationships,
    
- synthesis,
    
- priorities,
    
- semantic neighbourhood,
    
- thread structure.
    

Knowledge accumulates.

Interpretation evolves.

---

# The Semantic Embedding Space

The Research State exists as a high-dimensional semantic embedding space.

Each Note Block occupies a position within this space.

Its position emerges from

- manually curated metadata,
    
- explicit structural relationships,
    
- derived semantic similarities,
    
- organisational statistics.
    

The embedding does **not** represent artificial intelligence.

It represents the organisational geometry of scientific work.

---

# Organisational Dimensions

Metadata defines measurable organisational dimensions.

Examples include

- Project
    
- Thread
    
- Information Type
    
- Experimental Stage
    
- Publication Target
    
- Confidence
    
- Positivity of Result
    
- Review Status
    

Each dimension contributes independently to the geometry of the Research State.

Different dimensions may carry different weights.

The combination of all dimensions determines the position of each Note Block within the semantic space.

---

# Emergent Relationships

Relationships are primarily computed rather than manually authored.

They emerge from

- shared metadata,
    
- weighted organisational dimensions,
    
- structural relationships,
    
- semantic similarity.
    

Explicit parent-child relationships remain available where necessary.

However, the graph should primarily emerge naturally from the organisational measurements supplied by the researcher.

---

# Metadata as Measurement

Metadata should never be viewed as tagging.

Metadata represents measurements describing the current scientific interpretation of a Note Block.

These measurements collectively define

- similarity,
    
- proximity,
    
- organisational relationships,
    
- graph topology.
    

Metadata therefore becomes the statistical foundation upon which the entire Research State is constructed.

---

# User Input

There are only two fundamental forms of user interaction.

## Capture Knowledge

The researcher creates a new Note Block.

This permanently adds evidence to the project.

---

## Refine Interpretation

The researcher modifies metadata.

This changes the interpretation of existing evidence.

Everything else within the system is derived.

---

# Local Intelligence

Local intelligence exists solely to reduce interaction cost.

It may

- suggest metadata,
    
- recommend similar threads,
    
- identify related Note Blocks,
    
- autocomplete metadata,
    
- recommend likely organisational locations.
    

These suggestions should arise from lightweight local semantic analysis and existing organisational statistics.

Local intelligence must never

- generate scientific conclusions,
    
- propose biological mechanisms,
    
- infer truth,
    
- replace researcher judgement.
    

Its purpose is organisational assistance.

---

# Researcher Responsibilities

The researcher remains solely responsible for

- scientific reasoning,
    
- interpreting evidence,
    
- resolving contradictions,
    
- constructing theories,
    
- deciding truth.
    

The software never performs these tasks.

---

# Software Responsibilities

The software performs

- organisation,
    
- relationship computation,
    
- metadata suggestion,
    
- retrieval,
    
- visualisation,
    
- graph construction,
    
- similarity estimation,
    
- project state tracking.
    

The software organises.

The scientist reasons.

---

# Conflict Regions

Conflict is a first-class property of the Research State.

A conflict occurs when available evidence supports incompatible interpretations.

Conflict is not considered an error.

Conflict is a productive scientific signal.

The purpose of the Research State is to expose these regions rather than conceal them.

---

# Thread Formation

Threads originate from three primary sources.

## New Idea

A Note Block introduces an entirely new line of investigation.

---

## Unexplained Observation

Evidence cannot be comfortably incorporated into existing scientific understanding.

---

## Conflict

Contradictory interpretations emerge within the current Research State.

The system should encourage the creation of a dedicated investigation thread whose purpose is resolving the contradiction.

---

# Confidence

Confidence is a living property.

Confidence should change as evidence accumulates.

For example,

- stronger supporting evidence increases confidence,
    
- contradictory evidence decreases confidence,
    
- successful replication strengthens confidence,
    
- failed validation weakens confidence.
    

Confidence therefore represents the project's current belief rather than historical opinion.

---

# Review

Review is not housekeeping.

Review is the active refinement of the project's interpretation.

During Review, the researcher

- compares competing interpretations,
    
- resolves organisational inconsistencies,
    
- adjusts metadata,
    
- improves synthesis,
    
- creates new investigation threads,
    
- strengthens or weakens confidence,
    
- refines the current representation of scientific understanding.
    

The objective is not tidiness.

The objective is reducing the discrepancy between the Research State and reality.

---

# Continuous Reorganisation

Every meaningful modification to metadata should permit the Research State to reorganise.

As interpretation changes,

- relationships update,
    
- neighbourhoods shift,
    
- semantic regions evolve,
    
- graph topology adapts.
    

The graph is therefore continuously redistributing itself as scientific understanding matures.

---

# Publication

Publication represents the completion criterion of a project.

A publication is not merely a document.

It is the culmination of a sufficiently coherent and defensible Research State.

The graph should naturally reveal

- supporting evidence,
    
- remaining conflicts,
    
- missing experiments,
    
- confidence,
    
- logical structure.
    

The publication becomes a projection of the mature Research State.

---

# Fundamental Invariants

The following principles should never be violated.

- Evidence is immutable.
    
- Interpretation is mutable.
    
- The graph represents current understanding rather than historical belief.
    
- Metadata measures interpretation rather than acting as tags.
    
- Relationships emerge from organisational dimensions.
    
- Conflicts are scientific opportunities.
    
- Review refines interpretation rather than organising files.
    
- Local intelligence organises but never reasons.
    
- Every user-visible interface is a projection of the Research State.
    
- Publication is the natural endpoint of a mature Research State.
    

---

# Foundational Principle

> **The Research State is not a record of everything that has happened.**

> **It is the continuously updated best representation of what the project currently believes, constructed from immutable evidence and mutable interpretation.**

The Research OS therefore functions not as a knowledge management system, but as a dynamic epistemic operating system whose purpose is maintaining the current state of scientific understanding while preserving every piece of evidence that contributed to it.
